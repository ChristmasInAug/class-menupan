     Context

     현재 저장소는 그린필드 상태다. 실제 코드(server.mjs, package.json,
     public/)는 아직 없고 다음만 존재한다:

     - docs/menu-project-requirement.md — 원본 요구사항: Excel 탭 = 메뉴판
     페이지, chokidar 파일 감시 + SSE로 자동 갱신, _설정 시트로
     매장명/테마/자동전환초 제어, CSS 테마 2종(cafe-dark/bistro-light) 순수 변수
     방식.
     - design/project/메뉴판 템플릿 시스템.dc.html + design/project/assets/* —
     Claude Design 핸드오프 번들. 실제로는 테마 8종(bistro-light, cafe-dark,
     forest-dark, forest-light, light-olive, deep-green, beige, cream) ×
     디바이스 4종(signage 1080×1920, tablet-land 1920×1440, tablet-port
     1440×1920, mobile 1080×2160) 조합의 배경+테두리 PNG 에셋(총 64장)이 이미
     준비되어 있고, 컴포넌트 로직은 assets/<테마>/{bg,frame}-<디바이스>.png를
     배경/오버레이로 겹쳐 렌더링한다. 폰트는 Nanum Myeongjo(제목) +
     Pretendard(본문).

     그라데이션·글로우·장식 모션 금지 등 디자인 규칙.

     사용자는 켄트 벡 증강코딩(TDD: Red-Green-Refactor, Tidy First 구조적/행위적
     변경 분리, 커밋 규율)을 따라 앞으로 개발할 계획이며, /init으로 만들 문서를
     CLAUDE.md(개발 원칙+TDD 프로세스) / PRD.md(제품 요구사항) / TRD.md(기술
     요구사항)로 분리해 달라고 요청했다.

     확정된 방향(사용자 답변):
     1. 테마 아키텍처는 하이브리드: 기본은 CSS 변수 테마(가벼움,
     cafe-dark/bistro-light), PNG 배경+테두리 에셋 테마(8종 × 4디바이스)는 옵션
     확장 경로로 TRD에 둘 다 기술.
     2. PRD.md·TRD.md는 docs/ 폴더에 작성. CLAUDE.md는 루트 유지(Claude Code
     관례). 기존 docs/menu-project-requirement.md는 원본 그대로 보존.

     이 작업은 문서 작성만 한다 — 코드(server.mjs 등) 구현은 범위 밖.

     1. CLAUDE.md (루트, 신규)

     구성:
     - 프로젝트 한 줄 요약 + PRD.md/TRD.md 링크 안내
     - 개발 원칙 — 켄트 벡 증강코딩 TDD 프로세스 (WebFetch로 받은 원문 내용
     그대로 반영):
       - TDD 사이클: Red(실패하는 테스트 먼저, 행위 서술형 이름) → Green(테스트
     통과시키는 최소 구현만, 과도한 기능/최적화 금지) → Refactor(테스트 통과
     후에만, 한 번에 한 변경, 매번 재실행)
       - Tidy First: 구조적 변경(이름 변경/메서드 추출/이동, 행위 불변) vs
     행위적 변경(기능 추가/버그 수정) 절대 같은 커밋에 섞지 않음, 구조적 변경
     먼저
       - 커밋 규율: 테스트 전부 통과 + 린터 경고 해결 + 논리적 단위 하나 + 커밋
     메시지가 구조적/행위적 명시해야 커밋 가능. 작고 잦은 커밋.
       - 코드 품질 기준: 중복 제거, 의도 명확한 네이밍, 의존성 명시, 작은
     메서드/단일 책임, 가장 단순한 해법
       - 버그 수정 프로세스: API 수준 실패 테스트 → 최소 재현 테스트 → 둘 다
     통과시키는 구현
       - 실제 워크플로우(새 기능 추가 시 7단계 절차 그대로)
     - 이 프로젝트에서의 적용 방식: 테스트 러너 선택은 구현 시작 시점에
     정함(현재 코드 없음), 서버(server.mjs)/파싱 로직/SSE 브로드캐스트 각각에
     대해 Red-Green-Refactor 단위 명시, 커밋 메시지 prefix 예시(structural:,
     feat:, fix:) 제시
     - 코딩 스타일: .claude/rules/anti-ai-slop.md 참조(이미지/HTML 생성 시 적용)
     - 빠른 시작 명령 (원본 문서의 npm install / npm start 절 요약, 상세는
     PRD/TRD 참조)

     2. docs/PRD.md (신규)

     제품 관점 — "무엇을, 왜". 원본 menu-project-requirement.md 내용을 제품

     분리라는 강의 앵커 원칙
     - 핵심 사용자 시나리오: 점주가 Excel 수정 → 저장 → 브라우저 자동 갱신
     - 기능 요구사항: 시트=페이지 매핑, 메뉴 항목
     필드(메뉴명/가격/설명/품절/카테고리), 품절 표시 규칙, _설정
     시트(매장명/테마/자동전환초), 테마 선택(Excel에서 코드 수정 없이 변경),
     자동전환(디지털 사이니지)
     - 비기능 요구사항: 저장 시점에만 반영(로컬 xlsx 특성 고지), 갱신 지연
     허용치(디바운스 300ms 배경)
     - 응용 아이디어(강의 확장) 원본 그대로 이관: 테마 추가, 카테고리 그룹핑,

     - Out of scope: 이 문서 단계에서는 코드 구현 없음, 다국어/결제/재고연동 등
     언급 없으면 명시적 제외

     3. docs/TRD.md (신규)

     기술 관점 — "어떻게". 두 소스(원본 요구사항 + design 핸드오프 번들)를 통합:
     - 아키텍처 다이어그램(원본 문서의 동작 원리 블록 재사용): chokidar 감시 →
     디바운스 300ms → 파싱 → SSE push → 브라우저 재렌더
     - 폴더 구조(원본 문서 트리 기준, 실제 코드 아직 없음을 명시)
     - 스택: express, chokidar, xlsx(SheetJS, CDN URL 사용 — npm 레지스트리 
     아님, 이유 명시), SSE(WebSocket 아닌 이유: 읽기 전용 단방향)
     - Excel 파싱 규칙: 헤더 행, 가격은 숫자만, 품절 Y/빈칸, _ 접두 시트 제외
     - 테마 아키텍처 (하이브리드):
       - 기본: CSS 변수 테마 2종(cafe-dark/bistro-light),
     templates/board-grid.css 공통 레이아웃 + 테마별 오버라이드

     assets/<테마>/{bg,frame}-<디바이스>.png, frame은 중앙 투명 오버레이로 bg

     스케일링(design 컴포넌트의 u = min(d.w, d.h) 비율 로직 인용)
       - 두 방식 중 어느 쪽을 쓸지는 _설정 시트의 테마 값과 신규 디바이스(또는
     자동감지) 값으로 분기하는 것을 향후 구현 과제로 명시(이번 문서 단계에서
     코드 미작성)
     - API/이벤트 계약: GET /api/menu 응답 스키마(페이지 배열, 각 페이지=시트,
     항목 배열), SSE event: menu-updated 페이로드
     - 테스트 전략(CLAUDE.md의 TDD 프로세스와 연결): 파서 단위 테스트(품절
     Y/빈칸, 숫자 아닌 가격 등 경계값), SSE 브로드캐스트 통합 테스트, 디바운스
     타이밍 테스트
     - SheetJS CDN 설치 주의사항 원본 그대로 이관
     - 참고 자료: design/project/메뉴판 템플릿 시스템.dc.html,
