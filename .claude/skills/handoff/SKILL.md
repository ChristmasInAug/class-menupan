# handoff — 세션 인계

세션을 끝내기 전에 지금까지의 상태를 저장소 루트의 `.handoff.md`에 기록한다. 다음에 이 저장소를 여는 사람(또는 미래의 Claude)은 대화 기록을 못 보고 이 파일만 본다는 전제로 쓴다.

## 실행 순서

1. **기존 `.handoff.md`가 있으면 먼저 읽는다.** 이전 인계 내용을 덮어쓰지 말고, 그 사이에 끝난 항목은 ✅로 옮기고 실패했던 시도가 이번에도 재현됐는지 확인한다.
2. **실제로 상태를 확인한다** — 기억이나 대화 요약에 의존하지 않는다.
   - `git status`, `git diff`, `git log --oneline -10`으로 실제 변경분과 커밋 여부를 확인한다.
   - 방금 세션의 TodoWrite 목록이 있으면 그 상태(completed/in_progress/pending)를 근거로 쓴다.
   - "빌드된다", "동작한다" 같은 주장은 직접 명령을 실행해 나온 출력(마지막 몇 줄)을 근거로 첨부한다. 실행하지 않았다면 "확인 안 함"이라고 명시한다.
3. **아래 템플릿으로 `.handoff.md`를 작성한다.** 체크리스트 형식(`- [x]` / `- [ ]`)을 반드시 쓴다 — 다음 세션이 항목 단위로 이어받아야 하기 때문이다.
4. 작성 후 사용자에게 파일 경로와 요약을 한두 문장으로 알린다. 커밋은 사용자가 명시적으로 요청할 때만 한다.

## 템플릿

```markdown
# 핸드오프 — YYYY-MM-DD HH:mm

## ✅ 완료 (근거 포함)
- [x] <무엇을 했는지 한 줄> — 근거: <명령어/출력/파일 경로/스크린샷 등 구체적 증거>
- [x] ...

## ❌ 시도했으나 실패 / 보류 (반복 방지)
- [x] <시도한 것> — 원인: <왜 안 됐는지> — 참고: <다시 시도할 때 주의할 점, 이미 아닌 걸로 확인된 방법>
- [x] ...
(실패한 시도가 없으면 "없음"이라고 적는다. 항목을 지어내지 않는다. 이 섹션의 체크는 "해결됨"이 아니라 "시도가 끝났고 결과가 기록됨"을 의미한다 — 실패 사실 자체는 완료된 관찰이므로 `[x]`를 쓴다.)

## ⏳ 다음 할 일
- [ ] <다음에 해야 할 구체적 작업> (우선순위 순서로)
- [ ] ...

## 아직 안 한 것 / 범위 밖
- <착수하지 않은 항목이나 의도적으로 미룬 범위>

## 참고
- 관련 파일: <경로>
- 관련 문서/이슈: <링크나 파일>
```

## 작성 원칙

- **근거 없는 완료 표시 금지.** "구현함"이 아니라 "구현하고 `npm run build` 통과 확인함(출력 첨부)"처럼 검증된 사실만 ✅로 올린다. 검증하지 않은 작업은 ⏳로 내린다.
- **실패 항목은 재현 가능하게.** 다음 세션이 같은 삽질을 반복하지 않도록, 무엇을 시도했고 왜 실패했는지 원인까지 적는다. 단순히 "안 됨"만 적지 않는다.
- **다음 할 일은 실행 가능한 단위로 쪼갠다.** "리팩토링 마무리" 대신 "SignupPage의 agreement 상태를 useFormValidation으로 통합" 처럼 다음 세션이 바로 착수할 수 있는 크기로 쓴다.
- 파일은 저장소 루트의 `.handoff.md` 하나만 유지한다(요청 시 다른 이름/경로 사용 가능). 매번 새로 만들지 말고 갱신한다.
