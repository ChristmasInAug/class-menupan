@TDD-IMPLEMENTS.md
@CLAUDE.md

Green 단계를 **마일스톤 전체 범위**로 수행한다. 대상은 마일스톤이고, 그 안의 Task는 순서대로 하나씩 처리한다.

1. **마일스톤 선정**: `$ARGUMENTS`가 있으면 번호(M1~M6) 또는 매치 키워드로 일치하는 마일스톤. 없으면 🔴 Red 상태 Task가 하나 이상 있는 최상단 마일스톤. 대상 마일스톤에 🔴 Red Task가 하나도 없으면 먼저 `/tdd-red [마일스톤]`을 실행하라고 안내하고 멈춘다.
2. 선정한 마일스톤의 Task 표에서 🔴 Red인 Task를 위에서부터 순서대로 나열한다.
3. 각 Red Task마다 다음을 **하나씩 순서대로** 반복한다:
   a. 그 Task의 실패 테스트를 실행해 실패를 재확인한다.
   b. **그 테스트를 통과시키는 데 필요한 최소한의 코드만** 구현한다(CLAUDE.md Green 규칙 — 과도한 기능·최적화·일반화 금지). 하드코딩으로 일단 통과시키는 것도 이 단계에서는 허용된다 — 정리는 `/tdd-refactor`에서 한다.
   c. `npm test`로 전체 스위트를 실행해 회귀 없이 통과하는지 확인한다.
   d. `TDD-IMPLEMENTS.md`에서 해당 Task 상태를 🟢 Green으로 갱신하고 구현 파일 경로를 채운다.
   e. 다음 Red Task로 넘어간다.
4. 아직 ⬜ Todo인 다른 Task(같은 마일스톤이든 다른 마일스톤이든)의 기능을 미리 구현하지 않는다.
5. 마일스톤 전체 처리 후 `TDD-IMPLEMENTS.md`의 "마일스톤 목록" 표에서 해당 마일스톤 Task 진행 현황(N/M)을 갱신한다.
6. 커밋하지 않는다. 대신 처리한 Task들에 대한 행위적 커밋 메시지 초안을 제시한다 — 신규 기능이면 `feat: <설명>`, 버그 수정이면 `fix: <설명>`(Task별로 하나씩, 또는 마일스톤 단위로 묶을지는 사용자 판단에 맡긴다고 명시).
7. 처리한 Task 목록을 짧게 요약하고, 다음 단계로 `/tdd-refactor [같은 마일스톤]` 실행을 안내하며 끝낸다.
