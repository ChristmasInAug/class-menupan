@TDD-IMPLEMENTS.md
@CLAUDE.md

Red 단계를 **마일스톤 전체 범위**로 수행한다. 대상은 마일스톤이고, 그 안의 Task는 순서대로 하나씩 처리한다.

1. **마일스톤 선정**: `$ARGUMENTS`가 있으면 `TDD-IMPLEMENTS.md`의 "마일스톤 목록" 표에서 번호(M1~M6) 또는 매치 키워드로 일치하는 마일스톤 하나. 없으면 ⬜ Todo Task가 하나 이상 남아 있는 최상단 마일스톤. 대상 마일스톤을 찾을 수 없거나 이미 모든 Task가 ⬜ Todo가 아니면 그렇게 보고하고 멈춘다.
2. 선정한 마일스톤의 Task 표에서 ⬜ Todo인 Task를 위에서부터 순서대로 나열한다. 이미 🔴/🟢/✅ 상태인 Task는 건너뛴다.
3. 각 Todo Task마다 다음을 **하나씩 순서대로** 반복한다(여러 개를 한 번에 몰아 쓰지 않는다):
   a. 그 Task 설명에 맞춰, 행위를 서술하는 이름의 실패하는 테스트 하나만 작성한다(CLAUDE.md Red 규칙: 작은 단위, 실패가 명확하고 유용한 정보를 줘야 함).
   b. 테스트가 참조하는 모듈/함수가 없어도 **구현 코드는 절대 작성하지 않는다** — 테스트만 작성한다.
   c. `npm test`를 실행해 그 테스트가 의도대로 실패하는지 확인한다(엉뚱한 실패가 아닌지 확인). 실패 로그 핵심 줄만 간단히 보고한다.
   d. `TDD-IMPLEMENTS.md`에서 해당 Task 상태를 🔴 Red로 갱신하고 테스트 파일 경로를 채운다.
   e. 다음 Todo Task로 넘어간다.
4. 다른 마일스톤의 Task는 건드리지 않는다.
5. 마일스톤 전체 처리 후 `TDD-IMPLEMENTS.md`의 "마일스톤 목록" 표에서 해당 마일스톤 Task 진행 현황(N/M)을 갱신한다.
6. 커밋하지 않는다 — 커밋은 사용자가 명시적으로 요청할 때만 한다.
7. 처리한 Task 목록을 짧게 요약하고, 다음 단계로 `/tdd-green [같은 마일스톤]` 실행을 안내하며 끝낸다.
