@TDD-IMPLEMENTS.md
@CLAUDE.md

Refactor 단계를 **마일스톤 전체 범위**로 수행한다. 대상은 마일스톤이고, 그 안의 Task는 순서대로 하나씩 처리한다.

1. **마일스톤 선정**: `$ARGUMENTS`가 있으면 번호(M1~M6) 또는 매치 키워드로 일치하는 마일스톤. 없으면 🟢 Green 상태 Task가 하나 이상 있는 최상단 마일스톤. 대상 마일스톤에 🟢 Green Task가 하나도 없으면 먼저 `/tdd-green [마일스톤]`을 실행하라고 안내하고 멈춘다.
2. 선정한 마일스톤의 Task 표에서 🟢 Green인 Task를 위에서부터 순서대로 나열한다.
3. 각 Green Task마다 다음을 **하나씩 순서대로** 반복한다:
   a. 해당 Task 구현 코드를 CLAUDE.md 4절(코드 품질 기준)로 점검한다: 테스트 케이스에 맞춘 하드코딩·매직 리터럴, 중복, 불명확한 네이밍, 과도한 추상화, 숨겨진 의존성, 단일 책임 위반.
   b. 발견한 문제를 **한 번에 하나씩** 구조적 변경으로 고친다 — 이름 변경/메서드 추출/이동/중복 제거 등. 행위(테스트가 검증하는 결과)는 절대 바꾸지 않는다.
   c. 각 구조적 변경 직후 즉시 `npm test`로 전체 테스트가 여전히 통과하는지 확인한다. 실패하면 그 변경을 되돌린다.
   d. 손댈 게 없다고 판단되면 억지로 리팩터링하지 않는다 — 판단 근거를 한 줄로 남긴다.
   e. `TDD-IMPLEMENTS.md`에서 해당 Task 상태를 ✅ Done으로 갱신한다.
   f. 다음 Green Task로 넘어간다. 이미 같은 마일스톤에서 처리한 Task의 리팩터링으로 드러난 **마일스톤 내 다른 Task와의 중복**은 이 시점에 함께 정리해도 된다(같은 마일스톤 범위 내 구조적 변경이므로).
4. 마일스톤 전체 처리 후 `TDD-IMPLEMENTS.md`의 "마일스톤 목록" 표에서 해당 마일스톤 Task 진행 현황(N/M)을 갱신한다. 마일스톤의 모든 Task가 ✅ Done이면 그렇게 명시한다.
5. 커밋하지 않는다. 대신 구조적 커밋 메시지 초안을 제시한다: `structural: <설명>`(리팩터링이 전혀 없었던 Task는 "구조적 커밋 불필요"라고 명시).
6. 처리한 Task 목록을 짧게 요약하고, 다음 마일스톤의 ⬜ Todo Task를 안내하며 `/tdd-red [다음 마일스톤]`으로 이어가도록 제안하고 끝낸다.
